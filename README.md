# Проверка LTL через SPIN

Один скрипт, JSON-файлы с заданиями и общий шаблон Promela.
Python использует только стандартную библиотеку.

## Запуск

Из папки проекта:

```powershell
python run.py
```

Результат появится в консоли и в `build/<запуск>/report.txt`. Успешный отрицательный тест
тоже получает `PASS`: SPIN нашёл именно то нарушение, которое ожидалось.

В `config.json` уже указаны пути к установленным Windows-инструментам:

- SPIN: `%LOCALAPPDATA%/Programs/Spin/spin.exe`;
- GCC: `C:/msys64/ucrt64/bin/gcc.exe`;
- дополнительные утилиты: `C:/msys64/usr/bin`.

Эти пути взяты из разрешённого `SPIN/start-ispin.bat`. Скрипт не читает
папку `SPIN/`, не запускает iSPIN, не использует WSL и ничего не устанавливает.
PATH дополняется только внутри текущего Python-процесса и его дочерних команд.
При переносе на другой компьютер достаточно поправить `config.json`.

## Как добавить задание

Создать файл `tasks/имя_задания.json`. Структура на примере двух предикатов:

```json
{
  "predicates": ["a", "b"],
  "formula": "[] ((a && b) -> X (!a && !b))",
  "tests": [
    {
      "name": "reset",
      "note": "После совместного события оба сразу ложны.",
      "prefix": [
        {"a": 0, "b": 0},
        {"a": 1, "b": 1},
        {"a": 0, "b": 0}
      ],
      "expected": true
    }
  ]
}
```

Формула задаётся один раз в исходном файле задания. Копии в автоматически
созданных моделях, снимках входных данных и отчёте менять не нужно.
Имена предикатов — строчные латинские буквы, цифры и `_`, начиная с буквы;
нельзя использовать зарезервированные слова Promela. Имя теста — латинские
буквы, цифры, `_` и `-`.

Каждое состояние содержит все перечисленные предикаты. Разрешены значения
`0`, `1`, `false`, `true`. Поле `expected` принимает только `true` или `false`.
Ожидание выбирается по смыслу задания заранее, а не вычисляется из формулы.

`prefix[0]` задаёт начальное состояние. Остальные элементы — следующие моменты.
Если поля `loop` нет, после `prefix` все предикаты становятся равными `0`
и остаются такими бесконечно. Например, `prefix: [{"q": 0}, {"q": 1}]`
означает `0 → 1 → 0 → 0 → …`: ровно одно событие.
Чтобы задать периодическое продолжение, добавить, например:

```json
"loop": [
  {"a": 1, "b": 1},
  {"a": 0, "b": 0}
]
```

Получится `prefix`, затем `loop`, затем ещё раз `loop`, и так бесконечно.
Для постоянного ненулевого хвоста его нужно указать явно, например
`"loop": [{"q": 1}]` для задания с предикатом `q`.
Пустые `prefix` и явно указанный пустой `loop` считаются ошибками входных данных.

## Почему сохраняется смысл X

Начальные значения находятся в глобальных объявлениях, а каждый последующий
момент генерируется как один `d_step`. Все предикаты обновляются одновременно
для наблюдателя LTL. Между моментами нет отдельных охранных условий или
отладочных команд. Печать состояния для воспроизведения находится внутри
того же `d_step` и не добавляет шаг.

Хвост всегда задан явным бесконечным циклом, поэтому завершение процесса не
добавляет скрытый момент. Соседние одинаковые состояния не удаляются:
`11 → 11 → 00` отличается от `11 → 00`.

В начале каждого запуска проверяется, что SPIN умеет переводить `X`.
Далее для каждого теста выполняются команды:

```text
spin -o3 -a model.pml
gcc -O2 -DNOREDUCE -o pan.exe pan.c
pan.exe -a -b -m10000 -w18
```

`-o3` отключает объединение операторов SPIN, `-DNOREDUCE` отключает сокращение
частичных порядков, `-a` включает поиск принимающих циклов. `-b` позволяет
обнаружить превышение глубины, а `-w18` задаёт размер хеш-таблицы обычного полного
поиска (это не приближённый bitstate-поиск). Параметр GCC `-O2` оптимизирует
C-код и не объединяет логические моменты модели.

Документация: [X и требования к проверке](https://spinroot.com/spin/Man/ltl.html),
[d_step](https://spinroot.com/spin/Man/d_step.html),
[опции SPIN](https://spinroot.com/spin/Man/Spin.html),
[опции pan](https://spinroot.com/spin/Man/Pan.html).

## Какие примеры подготовлены

В `tasks/2.1 both_reset.json` — 16 тестов для совместного события `a` и `b`:
все четыре начальных состояния, правильный и запоздалый сброс, сброс только
одного предиката, отсутствие совместных событий, циклы и переход через границу
цикла. Проверяется и нарушение после ранее правильного срабатывания,
а также одновременный сброс обоих предикатов при отсутствии `loop`.

В `tasks/1.1 marriage_twice.json` — 14 тестов для «не менее двух раз»:
ноль, одно, два и три события, соседние события, начальные `q=0` и `q=1`,
постоянные и периодические хвосты.

Согласно `Task.md`, `q` обозначает событие в конкретный момент, а не состояние
«состою в браке». Поэтому `q=1, q=1` — два отдельных события. Без `loop`
после последнего элемента `prefix` идут нули: достаточно `0 → 1`, чтобы задать
ровно одно событие. Явный `"loop": [{"q": 1}]` означает бесконечно много событий.
Тесты с начальным `q=1` дополнительно проверяют требование о разных
начальных значениях; исходному предположению «сейчас не замужем» соответствуют
сценарии с начальным `q=0`.

## Отладка несовпадения ожидания

Запустить один тест:

```powershell
python run.py --test "2.1 both_reset/late_reset"
```

Ожидание берётся из поля `expected` выбранного теста в JSON. Для отладки
несовпадения временно измените это поле и запустите тест:

```powershell
python run.py --test "2.1 both_reset/late_reset"
```

Имя итогового отчёта захардкожено в скрипте: `report.txt`. Файл появится внутри
папки текущего запуска как `build/<запуск>/report.txt`.

В консоли и отчёте появятся `FAIL` и настоящий контрпример из SPIN:

```text
t=0: a=0, b=0 (prefix[0])
t=1: a=1, b=1 (prefix[1])
t=2: a=1, b=1 (prefix[2])
```

Нарушение обнаруживается до запоздалого сброса, поэтому последующего `00`
в этом контрпримере нет. Для нарушения свойства живости трасса может включать
отметку начала бесконечно повторяемого цикла.

Каждый запуск сохраняется в новой папке `build/<запуск>/`. Внутри каждого теста:

| Файл | Назначение |
|---|---|
| `case.json` | Снимок формулы и теста |
| `model.pml` | Модель с пометками `prefix[i]`, `loop[i]`, `default_zero` |
| `generate.log` | Команда SPIN и сообщения генерации |
| `compile.log` | Команда GCC и сообщения компиляции |
| `verify.log` | Полный результат проверки |
| `model.pml.trail` | Контрпример, созданный SPIN, если формула нарушена |
| `replay.log` | Подробное воспроизведение: строки модели, значения, автомат LTL |
| `trace.txt` | Краткая последовательность моментов из этого контрпримера |

Контрпримеры сохраняются и для ожидаемых нарушений с `PASS`.
Чтобы повторить воспроизведение, взять путь теста из отчёта:

```powershell
python run.py --replay "build/<запуск>/2.1 both_reset/late_reset"
```

Если ожидалось `false`, а формула выполняется, статус будет `FAIL`, но
контрпримера нет: в отчёте остаётся проверенная последовательность.

Для диагностики ограничения глубины можно выполнить:

```powershell
python run.py --test "2.1 both_reset/start_00" --depth 1
```

Результат будет сохранён в `build/<запуск>/report.txt`.

Это должно дать `ERROR`, а не успешный отрицательный тест. Можно также задать
`--timeout 30` — ограничение времени одной внешней команды в секундах.

Коды завершения Python: `0` — все тесты успешны, `1` — несовпадение ожидания,
`2` — техническая ошибка. Ошибка отдельного запуска не мешает проверить остальные
тесты. Ошибка входного JSON останавливает проверку до запуска SPIN и попадает
в отчёт. Старые модели и трассы не используются повторно.

## Устройство скрипта

В `run.py` основные функции расположены в порядке работы:

1. `load_tasks` — чтение JSON и проверка входных данных.
2. `generate_model` — подстановка в `template.pml`.
3. `run_command` — внешняя команда, тайм-аут и лог.
4. `parse_result` — различение выполнения, нарушения и технической ошибки.
5. `replay_trace` — воспроизведение контрпримера.
6. `run_test` — проверка одного теста целиком.
7. `write_report` — общий текстовый отчёт.
8. `main` — параметры запуска и цикл по тестам.

Проверки самого скрипта запускаются отдельно:

```powershell
python -m unittest -v test_runner.py
```

Они проверяют несовпадения ожиданий в обе стороны, воспроизведение реального
контрпримера, цикл для нарушения живости, ограничения глубины, тайм-аут,
неверный ввод, отсутствие компилятора и продолжение после ошибки формулы.
Также проверяется, что отсутствие `loop` добавляет нулевой хвост, а все
предикаты сбрасываются одним шагом.
